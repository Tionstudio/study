# Дальнейшие улучшения агента

Список того, чего не хватает реализации агента (`chat_agent.html`) до уровня
современных агентов. Уже реализовано: планирование с отображением плана,
параллельные и составные вызовы инструментов, стриминг мышления.

## Критично для практики

1. **Память между сессиями** — история живёт только в памяти процесса и умирает
   с «Новым диалогом»/перезапуском. Нужны: персистентные диалоги (SQLite, как
   в основном чате) и долговременная память (факты о пользователе, итоги
   прошлых сессий, подмешиваются в системный промпт).

2. **Самокоррекция / рефлексия** — после ошибки инструмента агент должен
   анализировать причину и менять подход, а не просто получать текст ошибки.
   Отдельный шаг «оцени результат и реши, достигнута ли цель».

3. **Перепланирование** — сейчас план составляется один раз в начале. При
   ошибке или изменении ситуации агент должен уметь пересмотреть план
   (частично закрыто инструментом `update_plan`, но без триггера «план не
   работает — пересмотри»).

## Важно для удобства

4. **Нативный function calling** — вызовы эмулируются текстовым
   JSON-протоколом. OpenAI-совместимое поле `tools` + структурированный
   `tool_calls` в ответе модели надёжнее: без парсинга текста и уловок
   для слабых моделей. Поддерживается kimi и LM Studio (частично).

5. **Бюджет задачи** — есть только лимит вызовов подряд. Нужны общий лимит
   шагов/токенов/времени на задачу и честное «не справился» вместо
   бесконечных попыток.

6. **Потоковый план** — фаза планирования сейчас блокирующая (ответ
   появляется после полного плана). Можно стримить шаги плана по мере
   генерации.

## Следующий уровень

7. **Больше инструментов**: веб-поиск, HTTP-запросы, выполнение кода
   в песочнице, работа с git — агент становится полезным за пределами
   директории `test/`.

8. **Подтверждение на уровне правил** — вместо «каждая операция отдельно»:
   политики вида «запись разрешена всегда, удаление — всегда спрашивать»,
   белые списки действий на сессию.

9. **Sub-агенты и делегирование** — порождение дочернего агента с отдельным
   контекстом для подзадачи (инфраструктура пакетного режима уже есть).

10. **Метрики агента** — успешность задач, среднее число шагов, доля
    ошибочных вызовов; выгрузка для анализа (стыкуется с пакетным режимом).
